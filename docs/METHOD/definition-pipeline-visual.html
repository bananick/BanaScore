Le Pipeline de Définition

3 phases pour transformer une idée brute en spécification actionnable avec prototype interactif — avant d'écrire une seule ligne de code.

Phase 1

🔍 Discover

Explorer, comprendre, cadrer le problème et la vision produit

  • Brief produit brut
  • Analyse compétitive
  • Personas & JTBD
  • CUJ / User Journeys
  • Vision draft
Phase 2

📐 Specify

Produire un Specs Book exhaustif pour chaque dimension du produit

  • Specs modulaires (14+ chapitres)
  • Data models & architecture
  • AI stack & agents
  • Design system & navigation
  • Business model & roadmap
Phase 3

🎨 Prototype

Construire des protos HTML interactifs pour valider l'UI et la navigation

  • Proto HTML statiques
  • Navigation complète
  • Écrans clés avec états
  • Design tokens live
  • Clickable, partageable

🔍 Phase 1 — DISCOVER
Explorer le territoire, comprendre l'utilisateur, cadrer la vision. Cette phase produit les fondations nécessaires au Specs Book.

📝 Brief Produit

Le brief brut : idée, problème, marché cible, intuitions business. Pas besoin d'être parfait — c'est le point de départ.

Input

🏆 Analyse Compétitive

Positionnement vs concurrents. Forces, faiblesses, opportunités. Ce que le produit fait mieux ou différemment.

Recherche

👥 Personas & JTBD

Qui sont les utilisateurs ? Quels jobs-to-be-done ? Quels pain points ? Noms, contextes, objectifs concrets.

UX Research

🗺️ User Journeys / CUJ

Les parcours critiques end-to-end. Actor → Trigger → Steps → States → AI interventions → Success outcome.

UX Design

🎯 Vision Draft

Mission, marché, proposition de valeur, différenciation. Premier jet qui sera affiné pendant SPECIFY.

Vision

⚡ Master Prompt

Le prompt calibré pour un modèle puissant (Gemini 2.5 Pro, Claude Opus) qui génère le Specs Book complet en une passe.

📐 Phase 2 — SPECIFY
Produire un Specifications Book exhaustif. Chaque chapitre couvre une dimension du produit avec assez de détail pour qu'un dev puisse builder sans deviner.

📖 01 — Vision & Strategy

Mission, ICP, wedge, pricing, scope MVP/P2/P3, non-goals

👥 02 — Personas

Personas nommées avec contextes, pain points, success states, JTBD

🏗️ 03 — Architecture

Stack technique, services, data flow, modules backend/frontend

🗺️ 04 — Journeys & CUJ

Parcours critiques : actor, trigger, steps, states, AI touchpoints

💾 05 — Data Models

Entités, schéma Firestore/SQL, relations, audit model, events

🧭 06 — Navigation

App map, IA, rail behavior, mobile nav, Double Drawer

📱 07 — Page Specs

Screen-by-screen : layout, zones, états (loading/empty/error/success)

🎨 08 — Design System

Couleurs, typo, spacing, composants, motion, a11y, dark mode

🤖 09 — AI Stack

Agents, orchestration, MCP/A2A, guardrails, model routing

💰 10 — Business Model

Pricing tiers, unit economics, competitive strategy, growth

📢 11 — Marketing

Landing pages, SEO, campaigns, growth loops

🔐 12 — Admin & Security

RBAC, GDPR, audit logs, tenant isolation, compliance

📊 13 — Analytics

KPIs, dashboards, feedback loops, success metrics

🛣️ 14 — Roadmap

Foundation → MVP → Phase 2 → Phase 3 avec milestones

🎨 Phase 3 — PROTOTYPE
Construire des protos HTML statiques, interactifs et partageables. Zéro dépendance, 100% visuel.

🏠 Home / Landing

Hero, search bar, discovery, CTA principal. Version guest et logged-in.

HTML Proto

📊 Dashboard

KPIs, quick actions, feed d'activité, état du système. Version admin.

HTML Proto

🧭 Navigation Shell

Rail + panels, Double Drawer en action, transitions A↔B.

HTML Proto

📱 Mobile Shell

Bottom nav, drawer, sheets. Même design language, adapté mobile.

HTML Proto

🔑 Key Flows

Les flux critiques CUJ : onboarding, booking, création, etc.

Interactif

🗂️ Proto Hub

index.html — page d'accueil qui liste et donne accès à tous les protos.

Navigation

💡 Principes des protos

📂 Format
HTML/CSS/JS statique — aucune dépendance, ouvrable dans un navigateur
🎨 Design
Applique les design tokens du Specs Book (couleurs, typo, spacing)
🧭 Navigation
Clickable — les liens entre protos fonctionnent
📱 Responsive
Desktop + Mobile viewport (pas de framework nécessaire)
🔄 Itératif
Les protos évoluent avec les specs — living prototypes

📐 Flow complet : Definition → Sprints

DISCOVER → SPECIFY → PROTOTYPE → project/ files → Sprint 001 → BUILD

Le pipeline de définition produit les docs/definition/. Quand le proto est validé, on extrait les fichiers project/ (VISION.md, DESIGN.md, ROADMAP.md, etc.) et on lance le premier sprint avec Junia.
